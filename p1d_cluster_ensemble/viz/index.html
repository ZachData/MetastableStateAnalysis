Is the structure in the tokens, the frame, or the null?

Each result here is a real run read against a null, and the null against a calibration on the same inputs (one null draw treated as data). Colour is z with positive = more structure than the null; outlined cells are in the null's 2.5 % tail on that side.

How to read this page

One rule. Every result is the real data against a null: a fake version of the data with no structure built in. Some nulls report structure where there is none, so each is also run on a calibration: one null draw treated as the data, where there is nothing to find. What counts is real minus calibration, never the real count alone.

  1. In a table, look for a large excess, not a large first number.
  2. Switch Checkpoint to step 0. An effect that survives there was not learned: it comes from the architecture, position or identical tokens. The converse does not hold: training can also learn a position code, so an effect absent at step 0 is not yet content.
  3. Switch Tokens to all tokens. An effect that appears only there is repeated strings.
  4. Click the cell. The heatmaps show which layers and prompts carry it.
  5. Switch Showing to calibration. That is what "nothing there" looks like for this statistic.
  6. Use the scatter plots for intuition only.

Where it stands: nothing here yet separates learned content from position. Trained tokens beat the Gaussian locally in every frame and show a 2-means excess at L17–24, but the Gaussian, like null A, keeps no position, so both may be position. Against null B, which keeps position, attention agrees with the residual's 2-way split only at L17–23, weakly, and step 0 shows part of it too. The null that would settle it (position kept, content randomised in the residual) is Parked in status-1d.md.

Which frame shows the most structure?

Records in the lumpier tail, real vs calibration, layers 1–24 × 7 prompts (repeated_tokens out, as in the report). The excess over calibration is what counts; a frame whose calibration also fires is not at nominal level. Pick a cell to map it by layer.

How to read this section

The null

  • For each prompt and layer: a Gaussian with the tokens' own mean and covariance, 200 draws of the same size, each normalised and clustered exactly as the tokens are.
  • A statistic the tokens beat is structure the covariance alone does not explain.

The frames (columns)

  • raw (blue): each token vector scaled to length 1.
  • centred (orange): the direction all tokens share is removed, then rescaled. That shared direction makes everything look alike.
  • no-rogue (green): the 3 coordinates that dominate the shared direction are zeroed first, then centred.

Item (3) · attention communities

Who attends to whom, against three nulls

How to read this section

The three nulls

  • A, the model's own attention on Gaussian tokens. It fires on position alone: the untrained model beats it. Beating A is not evidence of content.
  • B, each offset diagonal shuffled. Keeps how much a token looks 1, 2, 3… back; destroys which content attends to which. The closest thing here to a content test, but not a clean one: it fires on the calibration (a null-A draw) for modularity, λ₂, community count and locality, and step 0 beats it at L17–23 too.
  • C, each head replaced by the theory's softmax(β⟨u,v⟩) with its fitted β.
  • Records: layers 1–23 × 7 prompts = 161. Against B and C some statistics fire on almost all of the calibration too; there only the excess means anything.

The charts

  • Real value vs the null's mean: solid = real, dashed = the chosen null's mean, dotted (modularity only) = the idealised cosine head on the real tokens. Medians over prompts.
  • Agreement chart: one colour per frame; solid = real, dashed = null A. A's agreement is near 0 by construction, so part of the gap is position.
  • β per head: median with the middle 50 % shaded; R² below. This is #108's fit with a straight-line offset term. The 2026-09-29 refit with one term per offset gives 3.46 [1.55, 5.57] over L1–23, 12 % lower, mostly at L9–16 (status-1d.md "β refit").
  • Communities along the text: each token underlined in its community's colour (first 8 by first appearance, the rest grey); the sink is greyed. Long single-colour runs are recency, and the nulls show them too.
